# Security Policy

## Supported Versions

Only the latest release and the current `main` branch receive active security updates.

| Version | Supported          |
| ------- | ------------------ |
| main    | :white_check_mark: |
| < 1.0   | :x:                |

---

## Reporting a Vulnerability

We take the security of this project seriously. If you discover a vulnerability, please do **not** open a public issue.

### How to Report
* **GitHub Private Advisory (Preferred):** Submit via the repository's **Security > Advisories > Report a vulnerability** tab.
* **Email:** Alternatively, send an encrypted report to `security@example.com` (replace with project/maintainer contact email).

### What to Include
To help triage and resolve the issue quickly, include:
* Description of the vulnerability and its potential impact.
* Step-by-step reproduction steps or a minimal Proof of Concept (PoC).
* Affected versions, dependencies, or platforms/architectures.
* Any suggested remediation or patch (if available).

---

## Response & Disclosure Process

* **Acknowledgment:** Expect an initial response within 48–72 hours confirming receipt.
* **Assessment & Fix:** Maintainers will evaluate severity, assign a CVE if appropriate, and develop a patch in a private branch.
* **Coordinated Disclosure:** We follow coordinated vulnerability disclosure (usually 30–90 days, depending on severity) before publishing public advisories and release notes.

---

## Scope & Safe Harbor

Activities conducted in good faith under this policy are considered authorized. Maintainers agree not to pursue legal action against researchers who:
* Make a reasonable effort to avoid data destruction, privacy violations, or service disruption.
* Give maintainers adequate time to resolve the issue before public disclosure.
